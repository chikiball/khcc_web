01Overview

1.1 Purpose

KHCC Web is a Progressive Web App (PWA) for KHCC, a road-cycling club. It replaces the current patchwork of WhatsApp messages, spreadsheets, and shared documents with a single source of truth for rides, overseas trips, races, and club communication.

1.2 Scope

This document defines functional and non-functional requirements for the MVP and two follow-on phases. It is a living document — update as features ship.

1.3 Out of Scope (for now)

  • Native iOS/Android apps (PWA only; native is a future consideration).
  • Payment processing beyond deposit tracking — use Stripe/PayNow externally for Phase 1.
  • Full training-plan coaching tools — link out to TrainingPeaks/Strava instead.
  • E-commerce (kit shop) — backlog only.

05Functional Requirements

5.1 Phase 1 — MVP Phase 1

FR-1 Authentication & Onboarding

  • FR-1.1 — Sign up/in via email magic link, Google, or Apple.
  • FR-1.2 — New users complete profile (name, photo, pace group, bike, Strava handle, emergency contact) before accessing member features.
  • FR-1.3 — Admins can invite members via email, pre-assigning roles.
  • FR-1.4 — Password-less auth; sessions persist across devices.
Acceptance: A new user goes from landing → signed in → completed profile in under 3 minutes on mobile.

FR-2 Ride Calendar

  • FR-2.1 — Scrollable list of upcoming rides (default: next 14 days), sorted by date.
  • FR-2.2 — Ride card: date/time, title, start point, distance, elevation, pace group, rider count, 3 avatars + overflow.
  • FR-2.3 — Filters: pace group (A/B/C), no-drop only, date range.
  • FR-2.4 — Detail page: description, map pin, route link, full RSVP list, leader contact, weather forecast.
  • FR-2.5 — One-off OR recurring rides (e.g. "Every Saturday 5:45 AM").
  • FR-2.6 — Statuses: scheduled, weather-watch, cancelled, completed.
Acceptance: A member finds and RSVPs to the next matching ride in ≤ 3 taps from home.

FR-3 RSVP System

  • FR-3.1 — Tap "I'm In" to RSVP; one tap to withdraw.
  • FR-3.2 — Rides may be capped; over-cap RSVPs auto-waitlist.
  • FR-3.3 — Waitlist promotes FIFO on withdrawal.
  • FR-3.4 — Cutoff editable by leader (default: ride start time).
  • FR-3.5 — "My Rides" view for each member.
Acceptance: RSVP state syncs across devices within 2 seconds.

FR-4 Member Profiles & Directory

  • FR-4.1 — Profile: photo, name, pace group, bike(s), Strava link, bio, join date.
  • FR-4.2 — Emergency contact private — visible only to Admins and the Ride Leader of a ride the member has RSVP'd to.
  • FR-4.3 — Searchable/filterable directory (name, pace group).
  • FR-4.4 — Privacy toggles: hide full name / hide from directory.
Acceptance: Emergency contact is never exposed to unauthorised roles in any API response.

FR-5 Ride Leader Tools

  • FR-5.1 — Create ride form: title, date/time, start point (map picker), distance, elevation, pace group, route URL, description, cap, tags.
  • FR-5.2 — Edit/cancel with reason prompt; auto-notify RSVP'd riders.
  • FR-5.3 — View RSVP list with contact info.
  • FR-5.4 — Post ride-specific announcements.
Acceptance: A leader creates a recurring Saturday series in under 2 minutes.

FR-6 Announcements

  • FR-6.1 — Club-wide feed on home screen.
  • FR-6.2 — Pinned announcements appear at top.
  • FR-6.3 — Admins/leaders post; members react (👍❤️).
  • FR-6.4 — Optional web push notifications.
Acceptance: A pinned announcement is visible to all signed-in members on next app open.

FR-7 Notifications

  • FR-7.1 — Email: 24h-before ride reminder; cancellation immediate.
  • FR-7.2 — Web push (opt-in): new ride for your pace; ride cancelled; waitlist promotion.
  • FR-7.3 — In-app notifications bell with unread count.

5.2 Phase 2 — Trips & Strava Phase 2

FR-8 Overseas Trips

  • FR-8.1 — Trip page: title, destination, dates, cover image, itinerary with routes, hotel, flights, packing list, cost breakdown.
  • FR-8.2 — Signup flow: Interested → Deposit Paid → Confirmed → Cancelled.
  • FR-8.3 — Roommate / pairing preferences form.
  • FR-8.4 — Document vault: PDFs (insurance, visa, bike box specs).
  • FR-8.5 — Post-trip gallery: photos + aggregated ride stats.
  • FR-8.6 — Signup status managed manually by Trip Organiser (deposits tracked externally).

FR-9 Strava Integration

  • FR-9.1 — Connect Strava via OAuth from profile.
  • FR-9.2 — Auto-import ride activities tagged to KHCC rides (date/time match ± 1h).
  • FR-9.3 — Weekly mileage leaderboard (opt-out available).
  • FR-9.4 — KOM/QOM shoutouts auto-generated, admin-approved.
  • FR-9.5 — Graceful token refresh and revocation handling.

5.3 Phase 3 — Racing, Safety & Stats Phase 3

FR-10 Race Calendar

  • FR-10.1 — List of upcoming races (local + overseas): name, date, location, category, distance, deadline, registration URL.
  • FR-10.2 — Members flag "I'm racing" and category.
  • FR-10.3 — Club team view per race.
  • FR-10.4 — Post-race results entry, admin-verified.

FR-11 Season Leaderboard

  • FR-11.1 — Configurable points system (podium, participation).
  • FR-11.2 — Season-long leaderboard visible to all members.

FR-12 Live Ride Safety

  • FR-12.1 — Check-in: "Rolling" at start, "Safe Home" at finish.
  • FR-12.2 — Leader dashboard shows live check-in status.
  • FR-12.3 — Overdue alert if no "Safe Home" 1h past expected finish.

FR-13 Incident Reporting

  • FR-13.1 — Report: crash / near-miss / mechanical / hazard.
  • FR-13.2 — Attached to ride (if applicable) and geotagged.
  • FR-13.3 — Admin-only heatmap to inform route choices.

FR-14 Club Stats Dashboard

  • FR-14.1 — Club totals (km, elevation, rides, active members) — weekly/monthly/yearly/all-time.
  • FR-14.2 — Individual attendance streaks.

06Non-Functional Requirements

6.1 Performance

  • NFR-1 — FCP ≤ 1.5s on 4G, ≤ 3s on 3G (home).
  • NFR-2 — TTI ≤ 3s on mid-range Android.
  • NFR-3 — API p95 ≤ 400ms reads, ≤ 800ms writes.

6.2 Accessibility

  • NFR-4 — WCAG 2.1 AA compliance.
  • NFR-5 — Min tap target 44×44pt (gloves!).
  • NFR-6 — Pace group never by colour alone — always includes letter (A/B/C).
  • NFR-7 — Respect prefers-reduced-motion.

6.3 Responsive & Device Support

  • NFR-8 — Mobile-first; designs target 375px min width.
  • NFR-9 — Support iOS Safari 16+, Chrome 110+, Firefox 110+, Edge 110+.
  • NFR-10 — PWA: installable, offline cache for upcoming rides.

6.4 Security & Privacy

  • NFR-11 — HTTPS/TLS 1.2+ only.
  • NFR-12 — Supabase Auth; no plaintext passwords.
  • NFR-13 — Row-Level Security on all tables; emergency contact restricted.
  • NFR-14 — PDPA-aligned: data export + deletion on request.
  • NFR-15 — Strava tokens encrypted at rest.
  • NFR-16 — Audit log for admin actions.

6.5 Reliability

  • NFR-17 — 99.5% uptime target (excl. planned maintenance).
  • NFR-18 — Daily DB backups, 30-day retention.
  • NFR-19 — Graceful degradation when Strava/Mapbox/OpenWeather unavailable.

6.6 Internationalisation

  • NFR-20 — English at launch; i18n-ready codebase.
  • NFR-21 — Dates shown in local timezone; stored as UTC.
  • NFR-22 — Metric units default; imperial toggle in Phase 3.

6.7 Maintainability

  • NFR-23 — TypeScript strict mode.
  • NFR-24 — Unit test coverage ≥ 60% on core domain logic.
  • NFR-25 — All PRs pass lint + typecheck + tests before merge.
  • NFR-26 — Storybook component library (Phase 2).

10Risks & Mitigations

RiskLikelihoodImpactMitigation
Low adoption — members stay on WhatsAppMedHighCommittee champions; WhatsApp bot bridges ride links; onboarding session.
Strava API rate limitsMedMedAggressive caching; batch sync; token refresh handling.
Leader doesn't update cancellations in-appHighHighMulti-channel notifications; admin can cancel on leader's behalf.
Privacy concerns (emergency contacts, location)MedHighStrict RLS; explicit consent; PDPA compliance doc.
Scope creep (kit shop, coaching…)HighMedStrict phase gating; backlog board for deferred ideas.
Single maintainer burnoutMedHighDocument everything; recruit a second contributor early.

11Open Questions

Committee review needed. Answers to these will finalise v0.2 of this doc.
  1. Club branding — is #E63946 red correct, or does KHCC have official brand colours / logo?
  2. Club name — does "KHCC" have a full expansion to use in headings / meta tags?
  3. Geography — primary ride region (Singapore? Malaysia? SEA?) — affects timezone, weather, map defaults.
  4. Membership model — open signup, or invite-only by admin?
  5. Payments — integrate Stripe/PayNow for trip deposits in Phase 2, or keep external?
  6. Data residency — any requirement to host in a specific region?
  7. Ride capping norms — do rides typically have caps, or is it open participation?
  8. WhatsApp bridging — should we build a bot that posts new rides to the WhatsApp group?
